| D-027 | Task 0.5 sign-in done on 30 October 2026. `POST /api/auth/link` sends a one-time link (random 256-bit token, SHA-256 hash stored, single use enforced by a conditional update, 15 minutes, earlier unused links invalidated). The lookup and email run in the background job `send_sign_in_link`, so the request does the same work for known and unknown addresses; unknown addresses get no email and no account. Limits: 5 link requests per address and 20 per IP per hour (address hashed in the limiter key), 30 link consumptions per IP per 15 minutes. `POST /api/auth/link/consume` signs in and confirms the address; whoever has TOTP on lands in `mfa_pending`, as after password login. The email's language is the interface language in use when the link was requested. A link may return only to `/account` (fixed list). | D-006; REUSE.md warning on admin email links. | Default |
| D-028 | The 24-hour verification link also signs the learner in (it doubles as the first sign-in link) and stays valid for 24 hours, not 15 minutes, because people often confirm later. | D-029 | Passwords are optional for learners: sign-up without one is allowed; a learner may set, change (current password required) or remove (current password required) it on `/account`; changing or removing signs out other sessions. Admins cannot remove their password. | D-006. | Default |
| D-030 | TOTP secrets are encrypted at rest (D-011 done): Fernet (AES-128-CBC with HMAC-SHA256) from `cryptography`, key derived by HKDF-SHA256 from `TOTP_ENCRYPTION_KEY` or, when empty, `SECRET_KEY`; stored as `f1:<token>` in a 255-character column. Changing the key makes stored secrets unreadable and admins set up 2FA again. `cryptography>=42` added as a direct dependency (it was not installed before). | Maintained library, no hand-written cryptography. | Default |

| D-035 | What counts as a pass: entitlements from Stripe or granted by an admin; a trial does not. A pass cannot be bought while one is active for that canton; an extension needs a pass active or ended less than 90 days ago (`EXTENSION_GRACE_DAYS`). If two Checkouts are paid at once, the second pass extends the first by 6 months instead of overlapping. An extension for an active pass runs from its expiry, for a lapsed one from the payment time. An extension paid with no pass to extend (only possible by a race with a refund) starts a new 3-month entitlement. | Task brief; avoids double charges giving overlapping access. | Default |
| D-036 | Refund rule: within 14 days of the payment and fewer than 50 distinct questions answered since the payment (practice before buying does not count). Only the learner's latest payment is shown to them. An admin may refund outside the rule with an explicit override, which is recorded in the audit log. Access changes only on the `charge.refunded` webhook: a full refund ends a pass at the refund time, or takes an extension's months off again (not into the past); a partial refund changes no access. | Plan default "to confirm"; Chris may tighten. | Default |
