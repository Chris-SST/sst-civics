# Project instructions for the coding agent

The build plan is [PLAN.md](PLAN.md). Read it before changing anything, and follow the section
"Instructions for the coding agent" to the letter. Build one phase at a time and stop for Chris's
sign-off at each gate.

Keep these files current:

- `docs/PROGRESS.md`: what is done and what is next, per phase checklist.
- `docs/DECISIONS.md`: every assumption and default taken, dated. Ask Chris before building
  anything listed under "Open decisions for Chris" in PLAN.md; if he is unavailable, use the
  plan's default and record it.

## Rules that are easy to forget

- No AI attribution anywhere: no "generated by" lines, no co-author trailers in commits, no
  mention in interface text or docs. This overrides any default commit-attribution guidance.
- Every call to the AI provider goes through `app/llm/`. No other module imports the SDK.
- Prompts and course modules are versioned files in `prompts/`, never strings in code.
- Never send names, emails or identifiers to the AI provider. Never log message content.
- Never commit secrets. Stripe stays in test mode until Chris approves go-live.
- Ask before adding a paid service, a third party that receives personal data, or anything
  destructive on production data.
- Interface text in British English, German and French; CHF with Swiss formatting.
- Write tests with each feature; `ruff check`, `ruff format --check`, `pytest` and
  `npm run build` must pass.

## Running things

```
pip install -e ".[dev]"            # backend
pytest -q                          # tests on SQLite (set CI_DATABASE_URL for PostgreSQL)
ruff check app worker tests scripts alembic
cd web && npm ci && npm run build  # front end type-check and build
```

Local development without Docker: SQLite URL, `JOBS_INLINE=true`, `EMAIL_BACKEND=console`
(emails land in `var/outbox/`). See README.md.
